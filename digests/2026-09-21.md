### pnpm 12.4 — 跨生態系套件管理正式到位 `[工程知識]`

pnpm 12.4 在 9 月 10 日發布，最大亮點是**跨生態系套件管理（multi-ecosystem）**：同一個 workspace 現在可以同時管理 npm、Cargo（Rust）、PyPI（Python）套件，不再需要為不同語言各維護一套工具。對同時包含前端、Wasm 模組、Python 腳本的全端 monorepo 尤其方便——原本要分別執行 `npm install`、`cargo build`、`pip install`，現在一個 `pnpm install` 全部搞定。

這個功能的設計理念是讓 pnpm 成為「唯一要記的套件管理器」，特別是 AI 工具與 Wasm 工具鏈越來越常在前端 monorepo 出現的今天，跨語言依賴的統一管理需求已相當普遍。

```yaml
# pnpm-workspace.yaml（新增 ecosystems 區塊，pnpm 12.4+）
packages:
  - 'packages/*'   # npm 套件照舊
ecosystems:
  cargo:
    workspace: './rust-wasm'          # 含 Cargo.toml 的 Rust 目錄
  pypi:
    requirements: './scripts/requirements.txt'  # Python 依賴清單
```

```bash
# 以前：三個指令分開跑
npm install && cargo build && pip install -r scripts/requirements.txt

# 現在：一個指令搞定全部生態系的依賴安裝
pnpm install
```

### Safari 27 WebKit 新功能速覽 `[工程知識]`

Safari 27 正式推出，WebKit 團隊這次帶來幾項值得前端開發者留意的亮點。其中最受矚目的是**內建 MCP（Model Context Protocol）Server**——Safari 直接整合了 AI 情境協定，讓瀏覽器本身可以被 AI agent 呼叫，等於是把瀏覽器變成一個本地 AI 工具端點。另一個久等的功能是**完全可客製化的 `<select>` 元素**，告別多年來只能靠 `appearance: none` 硬蓋樣式的年代。

底層方面，WebKit 的 JSC 引擎核心模組完成了部分 ESM 重寫，這是長期技術債的清理。`<model>` 元素（直接在頁面嵌入 3D 模型）進入實驗支援，Scroll Anchoring 的改善也讓頁面在動態插入內容時的捲動位置更穩定。

```html
<!-- customizable <select>（Safari 27+）：終於可以直接用 CSS 樣式化 -->
<select>
  <option value="tw">台灣</option>
  <option value="jp">日本</option>
</select>

<style>
  /* 不需要任何 JS 或 custom dropdown hack，瀏覽器直接吃這個樣式 */
  select {
    background: #1e293b;
    color: white;
    border-radius: 8px;
    padding: 8px 12px;
    font-size: 14px;
  }
</style>
```

```js
// Safari MCP Server（實驗）：讓 AI agent 可以查詢當前頁面資訊
// 未來可能的呼叫方式（API 仍在制定中）
const context = await window.ai.getPageContext();
// → { url, title, selection, accessibilityTree, ... }
```

### Chrome 改為兩週一版：新功能更快抵達穩定版 `[工程知識]`

從 Chrome 153 起，Google 正式把發版週期從四週縮短為**兩週**。對前端開發者最直接的好處是：新的 Web API、CSS 功能、DevTools 改進到達穩定版的速度快了一倍，等新功能的煎熬時間減半。

過去四週一版是歷史包袱，當年跟隨 Firefox 節奏定下的。Chromium 工程流程改善後，兩週的 QA 週期已足夠。每個版本的變動量更少，升級更安全、更容易追蹤 breaking changes；安全性更新也能更快送到用戶手上。

舉個具體例子：假設你在 Chrome 154 Canary 測試到一個你需要的 CSS 新功能，以前要等約 8 週才能在穩定版使用，現在只要 4 週。Beta 與 Dev channel 的週期也同步壓縮，這個節奏改變同樣影響你對「瀏覽器支援」的估算方式。

### Kent C. Dodds 推出 Kody：AI 個人軟體工廠 `[知名工程師部落格]`

Kent C. Dodds（Epic Web、React Testing Library 作者）在 9 月 8 日介紹了他正在打造的 **Kody**——一個建立在 Cloudflare Workers 上的「個人軟體工廠」。核心概念是讓 AI agent 在你睡覺或做其他事情時，在沙盒環境中持續替你寫 code、執行測試、處理 PR。整個系統的程式碼量已超過 25 萬行，且幾乎全由 AI 協助撰寫。

Kody 的關鍵設計是**隔離性**：每個 AI 任務跑在獨立的 Cloudflare Worker 沙盒，不會互相干擾、不會污染主環境。Kent 用了一個生動的類比：就像你有一整個工廠的工人（agents），每個人在自己的工作台獨立作業，完成後才把成果送你審核，而你的角色是架構師，不是每一行 code 的撰寫者。

這篇文章也透露了他對 AI 輔助開發未來的想法：**工程師的工作從「寫每一行 code」轉變為「定義需求、審核成果、管理 agent」**。這個工作流程轉換對想思考 AI 開發模式的工程師而言很值得細讀。

### shadcn/lint：為 AI 生成 UI 設計的 Tailwind Linter `[GitHub Trending]`

`shadcn/lint` 是 shadcn（shadcn/ui 作者）最新推出的開源靜態分析工具，專門用來偵測 Tailwind CSS + shadcn/ui 專案中的設計系統違規。背景脈絡是：隨著 Cursor、Claude Code 等 AI 工具大量生成前端 code，設計一致性已成為一個新的工程問題——AI 很容易產出「功能正確但樣式混亂」的 UI，同一個意義的顏色可能用了三種不同的 Tailwind class。

作者測試結果顯示，在 agent-driven UI 工作流程中導入 lint，可減少 **10-48% 的 token 浪費**（因為 AI 不再需要在前後文中反覆「糾正」設計違規，減少來回）。工具可整合進 CI、pre-commit hook，或在 VS Code 中即時顯示。

```bash
# 安裝
npm install --save-dev @shadcn/lint

# 在 CI 中執行
npx @shadcn/lint check

# 範例輸出：
# ✗ Button.tsx:12 — 直接使用 text-blue-500，應改用設計 token: text-primary
# ✗ Card.tsx:8 — padding 不符規範，應使用 p-card 而非直接 p-4
# ✓ Dialog.tsx — 通過所有設計規則
```

```json
// .shadcnlintrc.json — 設定允許的設計 token 範圍
{
  "tokens": {
    "colors": "design-system",   // 只允許設計系統定義的色彩
    "spacing": "strict"           // 嚴格對齊 spacing scale，不允許任意數值
  },
  "components": {
    "enforce": ["Button", "Card", "Dialog"]  // 指定要嚴格檢查的元件
  }
}
```

### This Week In React #297：DevTools、Motion、Apollo `[前端技術棧]`

本期（9 月 16 日）最大亮點是 **React DevTools v8** 正式發布：Suspense Tab 預設開啟、新增 React Element 面板讓你在瀏覽器 Elements 分頁直接查看元件資訊、移除舊的 Timeline Profiler 改由 Performance Tracks 整合取代。另一個重要更新是 **React Router 8.4**：內部 data router context 拆成四個更細粒度的 Context，讓只用到 `useLocation` 的元件不會因為 `navigation.state` 變化就重新渲染，效能改善顯著。

**Motion（前 Framer Motion）** 本週宣布支援 React View Transitions，讓頁面切換動畫的宣告式寫法更簡潔自然。Apollo Client 4.3 改進了 field policies 對 scalar array 的型別推論，減少手動型別宣告的麻煩。Expo 58 Beta 也在本週開放測試，帶來更快的 Metro bundler 與 Expo Router 3.5。

```tsx
// React Router 8.4：更細粒度的 Context，減少不必要的重渲

function Breadcrumb() {
  // v8.4 後，這個元件只訂閱 "location context"
  // navigation.state 從 idle → loading 不會觸發它重渲
  // （以前任何導航狀態變化都會讓它重渲）
  const location = useLocation();
  return <nav aria-label="breadcrumb">{location.pathname}</nav>;
}

// 四個細粒度 context（v8.4 內部實作）：
// 1. LocationContext   → useLocation, useSearchParams, useMatches
// 2. NavigationContext → useNavigation, useRevalidation
// 3. DataContext       → useLoaderData, useActionData
// 4. FetcherContext    → useFetcher, useFetchers
```

### JavaScript Weekly #802：FP 知識圖譜、Zod 4.6 高速 validate `[前端技術棧]`

本期（9 月 15 日）的核心文章是「**Functional Programming Jargon, Mapped Out**」——一個互動式 FP 知識圖譜，把 functor、monad、applicative、semigroup 等術語的關係以視覺化方式呈現。點擊任何術語，立刻看到它與相鄰概念的關係脈絡，非常適合用來整理 FP 概念全貌，而非一個詞一個詞分開查。

另一個值得注意的更新是 **Zod 4.6** 新增的 `.validate()` 方法：相較於舊的 `.safeParse()`，`.validate()` 在只需要判斷「是/否合法」而不需要拿到詳細 error 時，速度快了 **35 倍**，非常適合高頻率的 runtime validation 場景，如表單即時驗證或 API 回應過濾。

```ts
// Zod 4.6：.validate() vs .safeParse() 使用場景對比

const EmailSchema = z.string().email();

// 需要 error 細節時（如顯示給使用者）：用 safeParse
const result = EmailSchema.safeParse(input);
if (!result.success) {
  console.log(result.error.issues[0].message); // 拿到具體錯誤訊息
}

// 只需要「合不合法」時（如過濾 API 回應陣列）：用 validate，快 35 倍
const validEmails = rawList.filter(item => EmailSchema.validate(item));
//                                          ↑ 直接回傳 boolean，無 error 物件開銷
```

```ts
// FP 知識圖譜中的 functor 概念，用前端熟悉的例子說明
// Functor = 可以被 map 的容器

// Array 是 functor
[1, 2, 3].map(x => x * 2); // → [2, 4, 6]

// Promise 也是 functor（map 就是 .then）
Promise.resolve(1).then(x => x * 2); // → Promise(2)

// 概念一致：把一個函數「提升」到容器內部執行，不需要打開容器
```

### What's New in Svelte: September 2026 `[前端技術棧]`

Svelte 官方每月更新摘要在 9 月中旬發布，這次的主角是 **Svelte 5.57**。`SvelteMap` 新增了 `getOrInsert` 和 `getOrInsertComputed` 兩個方法，解決「讀取不到就初始化」這個超常見的 Map 操作，一行取代原本的三行判斷；`createContext()` 現在也回傳第三個 `has` function，讓你可以在不觸發 get 錯誤的情況下安全地檢查 context 是否已設定。

另一個亮點是 `sv` CLI 的 `ai-tools` add-on：一鍵在 SvelteKit 專案中設定好 AI 開發工具（含 MCP 設定、agent 規則），取代了舊的 `mcp` add-on，名稱改為更通用的 `ai-tools` 也顯示 Svelte 生態系正在正式擁抱 AI-first 開發。`sv@next` 同步提供了 SvelteKit 3 的 task-based 自動遷移工具，讓現有 SvelteKit 2 專案可以按步驟逐漸升上 SvelteKit 3。

```ts
// Svelte 5.57：SvelteMap 的 getOrInsert / getOrInsertComputed

import { SvelteMap } from 'svelte/reactivity';

const cache = new SvelteMap<string, number[]>();

// 以前：三行（判斷 → 初始化 → 使用）
if (!cache.has('events')) cache.set('events', []);
cache.get('events')!.push(Date.now());

// 現在：getOrInsert 讓這個 pattern 壓縮成一行
cache.getOrInsert('events', []).push(Date.now());

// getOrInsertComputed：只在 key 不存在時才執行工廠函數（lazy 初始化）
// 適合初始化開銷較大的情況
const list = cache.getOrInsertComputed('heavy', () => computeExpensiveList());
```

```bash
# sv CLI 新增 ai-tools add-on（取代舊的 mcp）
npx sv add ai-tools

# 會在專案中自動產生：
# - .cursor/rules/      (Cursor agent 規則)
# - mcp.json            (MCP server 設定)
# - CLAUDE.md           (Claude Code 專案說明)
```

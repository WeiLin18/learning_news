1. **[React][工程知識] React Compiler Deep Dive: 自動 Memoization 是怎麼運作的**
   拆解 React Compiler 的內部流程：從 parse 到 AST 轉換，用 single static assignment 確保每個變數只被賦值一次，再用「effect 類型」（read/store/capture/mutate/freeze）判斷哪些值可以安全快取，藉此在編譯期自動插入 memoization，取代手動 `useMemo`/`useCallback`。範例對比：
   ```jsx
   // 以前：要自己判斷該不該 memo
   const sorted = useMemo(() => items.sort(cmp), [items]);
   // React Compiler 之後：直接寫原始邏輯，編譯器自動處理快取
   const sorted = items.sort(cmp);
   ```
   對想知道「這個編譯器到底做了什麼」而不只是「開啟它就變快」的 React 工程師是很扎實的深度解析。
   來源：Pockit Blog（開放搜尋補充）｜https://pockit.tools/blog/react-compiler-automatic-memoization-performance-guide/
   發布日期：2026-02（較早，約 6 個月前，確切日期建議上線前再核對）

3. **[React][架構][工程知識] A Deep Dive Into React Fiber**
   解釋 React Fiber 這個底層協調（reconciliation）架構：把渲染工作拆成一個個可中斷、可排優先權的「fiber」單元，讓 React 能在瀏覽器閒置時分批處理更新，而不會一次把主執行緒卡住。是理解 Concurrent Rendering、`useTransition` 等 API 為什麼能運作的地基知識。範例概念：
   ```
   一次大更新 → 拆成多個 fiber 單元 → 每處理完一個單元就檢查「還有時間嗎？」
   → 沒有就先讓瀏覽器處理使用者輸入 → 之後再繼續剩下的 fiber
   ```
   來源：LogRocket Blog（開放搜尋補充）｜https://blog.logrocket.com/deep-dive-react-fiber/
   發布日期：不確定（技術長青文，非時效性新聞，建議上線前確認是否為近期更新版本）

4. **[Vue][工程知識] Vue 3 Vapor Mode 深度解析：5 個核心原則**
   解釋 Vue Vapor Mode 這個「跳過 Virtual DOM」的編譯策略具體怎麼做：在編譯期把 template 直接轉成 DOM 操作指令,而不是在執行期做 diff。文章拆解其中的關鍵設計,例如編譯期就決定好哪些節點是靜態、哪些要綁定 reactive 更新,省掉執行期判斷的開銷。範例概念：
   ```html
   <!-- 傳統模式：執行期建立 VNode 樹再 diff -->
   <!-- Vapor 模式：編譯期直接產出 -->
   <script>
     const el = document.createElement('div');
     el.textContent = () => state.count; // 直接綁定，不經過 VNode
   </script>
   ```
   跟第 10 則「Vue 3.6 release notes」不同,這篇是專門解釋 Vapor Mode 技術原理的教學文,適合想理解「為什麼能快」而不只是「它快」的讀者。
   來源：toolsku 技術部落格（開放搜尋補充）｜https://www.toolsku.com/en/blog/vue3-vapor-mode-deep-dive-2026/
   發布日期：2026 年（確切日期跨來源比對略有落差，建議上線前再次核對）

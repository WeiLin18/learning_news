### 1. HTML Boilerplate 2026：每一行都有理由

`[工程知識]` `[HTML]`

Manuel Matuzović 整理了 2026 年版 HTML 文件起手式，對每一個標籤說清楚「為什麼要放、為什麼不要放」。從 `<meta charset>` 的必要位置，到 `<meta name="color-scheme">` 與 `prefers-color-scheme` 的執行時機差異，都逐一說明——不是讓你複製貼上的模板，是讓你「下次有人問為什麼這樣寫」能說出理由的參考。

最實用的兩個細節：

```html
<!DOCTYPE html>
<html lang="zh-Hant">
  <head>
    <!-- charset 必須是文件第一個 meta——瀏覽器解析其他標頭前就需要它 -->
    <meta charset="UTF-8" />

    <!-- viewport 防止手機縮放；initial-scale=1 修正 iOS Safari 字體自動縮小的 bug -->
    <meta name="viewport" content="width=device-width, initial-scale=1" />

    <!-- color-scheme 讓瀏覽器在套用你的 CSS「之前」就把系統 UI（捲軸、表單）切換主題
         可以消除深色模式下載入瞬間的「閃白」——CSS prefers-color-scheme 做不到這一點 -->
    <meta name="color-scheme" content="light dark" />

    <title>頁面標題</title>
  </head>
  <body></body>
</html>
```

`color-scheme` meta 比 CSS `prefers-color-scheme` 更早生效，是這篇最值得記下來的知識點。適合當作「下一次建新專案前的對照清單」，或轉給剛入行的同事當 HTML 基礎複習材料。

### 2. Chrome DevTools 152：SPA 的 Core Web Vitals 終於進 Live Metrics

`[工程知識]` `[DevTools]` `[Perf]`

Chrome DevTools 152 最受矚目的更新是 Live Metrics 面板現在**預設追蹤 SPA 軟導覽（soft navigation）的 LCP 與 INP**，底層升到 web-vitals v6.0.0。過去 SPA 切換路由不算一次「頁面瀏覽」，DevTools 量不到、RUM 也不回報；現在在本機就能直接看每個路由切換後的 CWV 數字，不必等線上 Field Data。

```text
// DevTools 151（升級前）：路由切換後 Live Metrics 沒更新
LCP: 1.2s  ← 一直停在初始載入的數字

// DevTools 152（升級後）：
[/product/123 → /product/456 軟導覽觸發]
LCP: 0.31s  ← 這次路由切換的新 LCP
INP: 52ms   ← 切換過程中的互動延遲
```

另外兩個值得留意的更新：

- **Network 面板** 新增「request resending」，可直接重送請求並帶上原始 payload（以前要到 Sources 面板手動設斷點才能重送 POST）。
- **DevTools MCP server** 改進——AI agent 可以呼叫更完整的 DevTools 工具列表，例如在 Claude Code / Cursor 裡讓 agent 幫你開 Performance 面板分析特定頁面。

📖 [Chrome for Developers](https://developer.chrome.com/blog/new-in-devtools-152) ｜ 2026-08-25 ｜ 優先來源

### 3. Web-Perf Wednesday 006：瀏覽器每兩週發版，你的 RUM 族群也在悄悄換人

`[工程知識]` `[Perf]` `[RUM]`

Harry Roberts（CSS Wizardry）的 Web-Perf Wednesday 系列第 6 篇：Chrome 和 Firefox 現在都往「每兩週一個主版本」靠近，比過去六到八週快了四倍。問題是——用戶一升版，你的 RUM 族群就換了一批人（新的瀏覽器能力、新的解析行為），有些指標會無緣無故改變，不是因為你部署了什麼。

```text
// 常見的「幽靈最佳化」情境：

週三早上：TTFB p75 突然降了 80ms
部署記錄：那天沒有任何發版

真正原因：
- 週二 Chrome 134 推送給 28% 用戶
- Chrome 134 預設啟用 HTTP/3 Early Hints
- → 這批用戶的 TTFB 起點不同了

教訓：先看「瀏覽器版本分布」有沒有明顯移動，再找其他原因
```

作者的建議很直接：在 RUM 儀表板加一個「瀏覽器版本分布」維度，每次主指標有波動先排查版本移動。雖然短小，但對正在追 Core Web Vitals 的團隊非常實用——這個陷阱大多數人都踩過，很少有文章把原因說得這麼清楚。

### 4. ponytail — 讓 AI agent 學會「能不寫就不寫」

`[GitHub Trending]` `[AI輔助開發]`

ponytail（117k ⭐）是一個 AI agent 插件，把「最懶的資深工程師」的決策邏輯注入 agent：在真正寫新程式碼之前，先強制走過七道決策梯——

1. 這段邏輯需要存在嗎？（YAGNI）
2. 現有 codebase 裡有嗎？
3. 標準函式庫能解決嗎？
4. 平台原生 API 能解決嗎？
5. 已裝的 dependency 能解決嗎？
6. 能一行解決嗎？
7. 才到：寫最小的必要實作。

```python
# 情境：要在兩個 config dict 之間做 deep merge

# 沒有 ponytail 的 agent：直接實作了 200 行自訂 deep_merge()
def deep_merge(dict1, dict2):
    result = dict1.copy()
    for key, value in dict2.items():
        if key in result and isinstance(result[key], dict):
            result[key] = deep_merge(result[key], value)
        else:
            result[key] = value
    return result

# 有 ponytail 的 agent：走到第 2 步就停住了
# → stdlib 的 dict union（|）在這個場景夠用
merged = {**base_config, **user_config}
# 結果：1 行，無外部依賴，測試更少，維護成本接近零
```

效果數據：同功能的產出程式碼平均少了 54%，token 成本降了 20%，執行速度快了 27%。支援 Claude Code、Cursor、Windsurf、GitHub Copilot 等 20+ AI agent 與編輯器，MIT 授權。核心理念：「減少的是不必要的程式碼，不是安全性或可讀性。」

### 5. archify — 用文字描述系統，自動產出可互動的架構圖

`[AI輔助開發]` `[DX工具]`

archify（34k ⭐）是一個 Node.js 工具，核心功能是把自然語言描述的系統架構轉成互動式 HTML/SVG 圖表，不需要手動拖拉節點。支援五種圖表類型：架構圖、工作流程圖、循序圖（sequence）、資料流圖、生命週期圖。

每張圖都是自包含的 HTML 檔案，可以直接用 email 傳、放 S3、存版本控制，不需要 Mermaid 伺服器或 Lucidchart 帳號。也作為 Cursor / Claude Code / OpenCode / Codex 的 agent skill 發布，在 `CLAUDE.md` 或 `cursor.rules` 加一行 import 就能讓 AI 在對話中直接產圖。

```bash
# 範例：用一行指令從文字描述生成循序圖
archify generate \
  --type sequence \
  --description "使用者登入：client → auth-service（JWT 驗證）→ user-db（查帳號）→ session-service（發 token）→ client（返回 access token）" \
  --output login-flow.html
# 結果：開啟 login-flow.html，可互動、可縮放、可匯出成 PNG
```

設計理念特別強調「truthful interaction」——圖表只呈現你明確定義的元件關係，不讓 AI 自己推論拓撲，所以不會出現「AI 猜錯了模組之間的連線方向」的問題。適合技術文件、架構評審、onboarding 材料。

### 6. GitNexus — 為 AI agent 建立程式碼知識圖（17 個 MCP 工具）

`[AI輔助開發]` `[MCP]` `[DX工具]`

GitNexus（46.5k ⭐）把 codebase 的函式依賴、模組邊界、執行路徑索引成一張知識圖，再透過 17 個 MCP 工具讓 AI agent 查詢。解決的痛點：AI agent 幫你改程式碼時，常因不知道「改這個函式會影響哪裡」而漏改、漏測，或建議出無法執行的答案。

```bash
# 第一步：建立索引（結果存到 .gitnexus/ 並 gitignore）
gitnexus analyze --repo ./my-app

# 之後在 Cursor / Claude Code 裡問 agent：
# 「如果我改 CartService 的 calculateTotal，會影響哪些元件？」

# agent 呼叫 impact MCP 工具，回傳：
# ✓ CheckoutPage.tsx（直接呼叫）
# ✓ OrderSummary.tsx（透過 useCartStore hook）
# ✓ 3 個相關 Vitest 測試案例需要更新
# ✓ 影響 2 個 API endpoint handler
```

兩種使用方式：CLI 本機建索引（不上傳原始碼），或瀏覽器版（WebAssembly 全程在瀏覽器端運算）。整合 Cursor、Claude Code、Codex。17 個 MCP 工具包含 query、context、impact、trace、detect_changes、rename、API impact analysis 等。特別適合多人大型 codebase——agent 不需要「猜」影響範圍，直接查知識圖。

### 7. What's new in Svelte: August 2026

`[Svelte]` `[前端技術棧]`

Svelte 八月生態系月報，這篇不是 SvelteKit 3 RC 的重複（那份公告在上次日報已收錄），主要涵蓋 kit 2.69/2.70 的 API 更新與社群新工具。

**最實用的 API 更新：remote forms 新增 `submitted` 屬性**。原本 form 送出後要等 `use:enhance` 的 success 或 fail 回呼才能更新 UI，現在可以直接讀 `submitted` 這個送出後立即為 `true` 的屬性——不需要額外管理一個 boolean 來做「送出中」的 loading 狀態：

```svelte
<script>
  import { enhance } from '$app/forms';
</script>

<form method="POST" use:enhance>
  <!-- submitted 在按下送出後立即 true，不等 server 回應 -->
  <!-- 用來做 loading 狀態不需要再開一個額外的 isSubmitting boolean -->
  {#if $page.form?.submitted}
    <span>處理中...</span>
  {:else}
    <button type="submit">送出表單</button>
  {/if}
</form>
```

另外兩個更新：`defineEnvVars` 搬到 `@sveltejs/kit/env` 子路徑（讓 tree-shaking 更乾淨）；社群方面 **PlaySocket** 帶來 CRDT 同步的多人協作 library，**Edra v3** 的 SvelteKit 富文字編輯器推出 headless 版本，可接 shadcn 元件。

### 8. agent-skills — Addy Osmani 整理的 25 個 AI coding agent 工程技能

`[AI輔助開發]` `[實務指南]`

Addy Osmani（前 Google Chrome 工程師、《Learning JavaScript Design Patterns》作者）整理的 AI coding agent 技能集合，目標是讓 AI agent 的產出帶有「資深工程師的紀律」。收錄 25 個技能，橫跨開發週期六個階段（Define、Plan、Build、Verify、Review、Ship），另附 4 個專家角色（code reviewer、test engineer、security auditor、web performance auditor）。

兩個具體範例說明它怎麼改變 agent 行為：

```yaml
# 在 CLAUDE.md 或 .cursor/rules 引入：
skills:
  - "agent-skills/skills/spec-driven-development.md"
  # 效果：agent 在動手寫程式前先回答「解決誰的問題？驗收標準是什麼？」

  - "agent-skills/skills/test-driven-development.md"
  # 效果：強制 red → green → refactor 循環，先跑失敗的測試再寫實作

  - "agent-skills/skills/code-review-and-quality.md"
  # 效果：merge 前五軸檢查（正確性、可讀性、安全、效能、測試覆蓋率）
```

和第 4 則的 ponytail 定位互補：ponytail 控制「要不要寫新程式碼」，agent-skills 控制「怎麼有紀律地寫」。兩者可以同時啟用，適合打算把 AI agent 引入團隊 workflow、但擔心品質難以控制的工程師。

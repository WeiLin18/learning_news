6. **[Blog][UX] Lea Verou — Dark mode toggles: two states are enough**
   Lea Verou 挑戰「深色模式切換鍵必須有三種狀態（跟隨系統、淺色、深色）才算完整設計」的普遍慣例，主張多數情境下兩種狀態的切換鍵就能完整表達使用者意圖。她的核心論點是：使用者去點擊網站上的切換鍵時，通常是想「立刻改變眼前畫面」，而不是要在設定頁預先聲明未來偏好，因此把三態選單塞進頁面內反而增加認知負擔卻沒對應到真實使用情境。範例情境：
   ```
   兩態切換鍵：切換鍵直接反映「目前顯示的是深色還是淺色」,
              並在初次載入時用 prefers-color-scheme 決定預設值(等同隱性支援「跟隨系統」)
   三態選單：使用者要先理解「跟隨系統」是什麼意思,才能決定要不要選它——多一層判斷
   ```
   她也點出三態控制在「獨立設定頁」（而非頁面內快速切換鍵）情境下才真正合理的例外狀況。是她一貫「介面狀態設計應對應使用者目標，而非照搬底層實作邏輯」論點的延伸，本質是互動設計哲學而非 CSS 語法教學。

    由 React 團隊成員 @eps1lon 提交（PR #96405），對仍在維運 Next.js 15.x LTS 生產環境、尚未升級到 16.x 的團隊是需要優先確認的資安修補。直接開啟 GitHub Release 頁面確認過內容。

15. **[測試][Vitest] Vitest 5.0 進入 beta：`clearMocks` 預設改為 true、benchmark API 重寫**
    Vitest 5.0 目前仍在滾動式 beta，幾個值得注意的變化：`clearMocks` 預設改成 `true`（每個測試前自動呼叫 `vi.clearAllMocks()`），`bench` 不再是從 `vitest` 直接 import 的頂層函式，改成從 test context 裡的 fixture 取得，並新增「pluggable benchmark provider API」讓你能替換 benchmark 的執行引擎。範例（遷移後寫法）：
    ```ts
    // v4:從 vitest 直接 import bench
    import { bench } from 'vitest';
    // v5 beta:bench 改成從 test context 的 fixture 取得
    test('bench example', ({ bench }) => {
      bench('sort array', () => { [...arr].sort(); });
    });
    ```
    對已經在用 Vitest 4.x 的團隊，這代表升級到 5.0 時 mock 行為與 benchmark 寫法都要重新檢視，建議先看 migration guide。直接開啟 GitHub Release 頁面確認過內容。

1. **[架構][設計流程][工程知識] Code, Craft, and the Making of Nested Folders**
   Figma 工程團隊記錄他們如何在既有產品裡加入「巢狀資料夾」（最深 10 層、權限可從父層資料夾繼承）這個看似單純的功能，實際上卻得重寫底層的內容/權限模型，牽動檔案瀏覽器、管理員控制台、共享機制三大子系統。文中最值得參考的是他們的協作方式：團隊乾脆放棄冗長的需求文件（PRD）辯論，直接在真實 codebase 裡做出可運作的 demo 來溝通設計決策，「一個能跑的 demo 永遠勝過一份 PRD」，過程中設計師與工程師的角色分工也刻意模糊化，讓兩邊都能直接動手改程式碼或設計稿。範例情境：
   ```
   傳統流程：PM 寫 PRD → 設計師畫稿 → 工程師依文件實作 → 發現邊界案例才回頭修文件
   Figma 這次流程：工程師先做出巢狀資料夾的可運作 demo → 設計師直接在 demo 上調整互動細節
   → 兩邊來回迭代 demo 本身,而非文件
   ```
   對正在思考「大型既有產品要怎麼安全加入結構性新功能」以及「設計師工程師協作模式」的團隊,是一篇具體的實戰記錄。
   來源：Figma Blog（開放搜尋補充）｜https://www.figma.com/blog/code-craft-and-the-making-of-nested-folders/

   資安研究機構 Manifold Security 揭露一起名為「evil twin」的供應鏈攻擊：攻擊者把 77 個真實存在的 Open VSX（VS Code 相容擴充功能市集）擴充功能原封不動複製一份，換成不相干的帳號重新上架、版本號固定寫死成 `0.0.1`，並把裡面的 `extension.js` 換成會回傳資料的版本，且刻意偽裝成「匿名使用量統計」規避使用者警覺。其中 58 個只回傳基本主機資訊，19 個更進一步蒐集作業系統細節、機器 ID、Git repo 中繼資料，甚至 GitHub／Azure DevOps 的 CI／雲端身份憑證，全部回傳到一個在第一個假套件上架前僅 11 天才註冊的網域。惡意套件於 7/26 至 8/1 間陸續上架，Open VSX 已於 8/3 全數下架。範例情境：

9. **[框架比較][Signals][工程知識] Signals Won the Framework War Except in React: A Developer Guide to Runes and Fine-Grained Reactivity in 2026**
   梳理 Svelte 5 runes、Vue 3.6、Solid、Angular signals 這幾個框架如何不約而同走向「細粒度、表達式層級」的依賴追蹤——畫面更新時只精準改動真正變化的那個 DOM 節點，而不是重新比對整棵元件樹；相對地，React 選擇了不同的路線，繼續靠 React Compiler 在建置期自動插入 memoization，而不是把 reactivity 模型本身換成 signals。範例概念（兩種模型的更新粒度差異）：
   ```
   Signals 模型（Svelte/Vue/Solid/Angular）：
     count.value++ → 只有讀取 count 的那個 DOM 節點被更新
   React Compiler 模型：
     setCount(count + 1) → 編譯器自動判斷哪些元件需要重新渲染,插入對應 memo
   ```
   對正在比較「不同框架的 reactivity/狀態更新機制到底差在哪」的團隊，這篇提供了一個清楚的分類框架，但本則僅能透過 WebSearch 交叉比對取得內容、無法直接開啟原始頁面驗證，信心度低於本日其他項目，建議上線前務必人工核對細節。
   來源：jsmanifest.com（開放搜尋補充）｜https://jsmanifest.com/signals-runes-fine-grained-reactivity
   發布日期：2026-05-31（較早，約 9 週前）

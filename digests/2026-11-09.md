### 1. What you need to know about View Transitions in React

`[工程知識]` `[React]` `[動畫]`

React 19.3（2026/09/09）把 `<ViewTransition>` 從實驗性 API 升格為穩定版。這篇 codeminer42 的指南從「什麼會觸發動畫、什麼不會」切入，澄清最常見的誤解：`<ViewTransition>` 不是讓裡面每個元素都動起來的魔法盒，它只給最近的一個 DOM 節點加 `view-transition-name`，並且**只有在 `startTransition()` 或 router navigation 內部觸發的狀態更新**才會啟動動畫。

最基本的用法：

```jsx
// 預設效果：cross-fade（瀏覽器原生的 View Transition 淡入淡出）
<ViewTransition>
  {showDetail ? <DetailView /> : <ListItem />}
</ViewTransition>

// 重點：一定要包在 startTransition 裡才會觸發動畫
// 直接 setState 不會有效果
startTransition(() => setShowDetail(true));
```

進階場景是 Shared Element Transition：同一個 `name` 在兩個不同頁面各放一個 `<ViewTransition>`，React 偵測到「一個移除、另一個插入」時，會自動在兩者之間執行移動動畫（類似原生 iOS 的共用元素轉場效果）：

```jsx
// 列表頁：縮圖
<ViewTransition name="product-hero">
  <img src={product.thumb} />
</ViewTransition>

// 詳情頁：大圖（同一個 name → 頁面切換時自動補間移動）
<ViewTransition name="product-hero">
  <img src={product.fullImage} />
</ViewTransition>
```

適合正在導入 React 19.3 的專案，尤其是需要流暢頁面轉場的電商、內容瀏覽類 App。

### 2. SvelteKit 3：從 SvelteKit 2 官方遷移指南

`[工程知識]` `[SvelteKit]` `[遷移]`

SvelteKit 3 在 2026/10/01 正式釋出，兩個最大的 breaking change：設定檔從 `svelte.config.js` 移進 `vite.config.js`，以及 `$lib` 路徑別名改為 `#lib`（改用 Node.js package.json 的 subpath imports 機制）。官方同時釋出 `sv` CLI 1.0，提供一鍵遷移指令。

版本門檻同步拉高：Node.js ≥ 22.17、TypeScript ≥ 6、Svelte ≥ 5.57.1、Vite ≥ 8.0.12。如果你的 CI pipeline 或 Docker build script 有寫死 `svelte.config.js` 路徑，遷移前要先清查。

```bash
# Step 1：自動遷移（大多數改動都能自動處理）
npx sv migrate sveltekit-3

# Step 2：檢視 diff，重點確認
# - svelte.config.js 的選項已移入 vite.config.ts 的 sveltekit() plugin
# - 所有 import $lib/xxx 已改成 import #lib/xxx
# - package.json 有新增 "imports" 欄位定義 #lib
```

遷移後的 `vite.config.ts` 樣板：

```ts
// vite.config.ts（遷移後——以前在 svelte.config.js 的選項都移進來）
import { sveltekit } from '@sveltejs/kit/vite';
import adapter from '@sveltejs/adapter-node';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    sveltekit({
      adapter: adapter(),   // 以前是 svelte.config.js 的 kit.adapter
    })
  ]
});
```

Remote Functions 功能在 SvelteKit 3.0 尚未完工，預計之後版本釋出。若你有自訂 `$lib` 以外的 path alias，遷移工具可能需要手動補上，詳見官方遷移指南。

📖 [svelte.dev 官方遷移文件](https://svelte.dev/docs/kit/migrating-to-sveltekit-3) ｜ 2026-10-01 ｜ 優先來源

### 3. TanStack AI 1.0：你的 AI、你的規則，穩定版來了

`[工程知識]` `[AI輔助開發]` `[SDK]`

TanStack AI 在 2026/10/23 發布 1.0 穩定版，主題是「Still Your AI, Still Your Way」：76 個套件同步升穩，包含 24 個 LLM provider 整合（OpenAI、Anthropic、Gemini 等）、AG-UI 協定支援、媒體生成、MCP、sandbox 和持久化。重要提醒：Agent Harness 功能仍維持 0.x，不在這次的穩定保證範圍內。

用 React 接 OpenAI 的最簡範例：

```tsx
import { useChat } from '@tanstack/ai-react';

function ChatBox() {
  const { messages, input, handleInputChange, handleSubmit } = useChat({
    provider: 'openai',
    model: 'gpt-4o',
    // 切換到 Anthropic 只要改這兩行——其他程式碼完全不用動
  });

  return (
    <>
      {messages.map(m => (
        <p key={m.id}>{m.role}: {m.content}</p>
      ))}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
        <button type="submit">送出</button>
      </form>
    </>
  );
}
```

從 RC 升到 1.0 的 breaking change 是移除已廢棄 API（RC 0.x 裡已有替代方案），以及 Client 和 Server 套件必須在同一個 major version。如果你的前後端分開部署，需確認兩邊同步升版。

### 5. Redux Toolkit 2.14.0：50 倍 dispatch 效能、RTK 3.0 路線圖出爐

`[前端技術棧]` `[Redux]` `[效能]`

RTK 2.14.0 在 2026/11/08（今天）正式發布，以效能為主軸。最亮眼的是 listener middleware 優化：在有 200 個 listener 的情境下，不相關 action 的 dispatch 吞吐量從 10.8 萬 ops/sec 暴升到 534 萬 ops/sec（約 50 倍），秘訣是「讓 middleware 在確認 action 不相關時直接 skip，不再逐一跑過所有 listener」。

API 層面的兩個重要變化：

```ts
// 1. RootState 正式 deprecated，改用 ApiRootState
// 舊做法（3.0 將移除）
import { RootState } from '@reduxjs/toolkit/query';
type MyState = RootState<typeof api>;

// 新做法——更精確，只含這個 api 的 slice state
import type { ApiRootState } from '@reduxjs/toolkit/query';
type MyState = ApiRootState<typeof api>;

// 2. 新的 DevTools sanitizer：讓 RTK Query action 顯示可讀名稱
import { createApiActionSanitizer } from '@reduxjs/toolkit/query';
const store = configureStore({
  devTools: {
    // 以前 DevTools 顯示一長串 UUID，現在改顯示 endpoint name
    actionSanitizer: createApiActionSanitizer(api),
  },
});
```

Entity adapter 也加了兩個實用 method：`removeMany({ where })` 可以用欄位條件批次刪除（例如 `removeMany({ where: { status: 'deleted' } })`），`selectByIds` 保留輸入的 id 順序回傳。RTK 3.0 路線圖同步公布，`RootState` 是首批確認會被移除的 API，建議趁這次升版順手遷移。

### 6. shadcn/ui October 2026：Trace、Code Block 與 AI Elements

`[前端技術棧]` `[React]` `[AI輔助開發]`

shadcn/ui 在 2026 年 10 月釋出三個專為 AI 應用場景設計的新元件：Trace（呈現 AI agent 的思考步驟與動作序列）、Code Block（顯示 agent 執行的指令與輸出），以及 AI Elements——一套取代原本 AI SDK Elements 的 copy-in patterns，沒有 npm package，直接把程式碼複製進專案，shadcn 的更新不會強制你跟進。

```bash
# 安裝 Trace（追蹤 AI agent 的操作步驟）
pnpm dlx shadcn@latest add trace

# 安裝 Code Block（顯示 AI 產生的程式碼與指令輸出）
pnpm dlx shadcn@latest add code-block
```

使用方式範例：

```tsx
// AI 聊天介面裡顯示 agent 的完整執行過程
export function AgentResponse({ steps, code }: Props) {
  return (
    <div>
      {/* Trace：列出 agent 的「思考→動作→輸出」序列 */}
      <Trace steps={steps} />

      {/* CodeBlock：顯示 agent 產生的程式碼，附語法高亮 */}
      <CodeBlock language="tsx">{code}</CodeBlock>
    </div>
  );
}
```

原本用 AI SDK Elements 的專案不需要立刻遷移（舊元件仍然可用），但每個 AI Elements 的文件頁面都附有給 coding agent 的 migration prompt，可以讓 AI 自動幫你轉換。

### 8. cloudflare/vinext：讓 Next.js App 跑在 Vite 上

`[前端技術棧]` `[Vite]` `[Next.js]`

Cloudflare 開源的 `vinext` 讓你用 Vite 的開發體驗（快速 HMR、esbuild 加速）跑 Next.js App——包含 App Router、middleware、API routes、`next/*` module imports，以及 `next.config.js`，幾乎全部不用改。切換方式極簡：

```bash
# 安裝
npm install vinext

# package.json scripts 改成 vinext 的等效指令
{
  "scripts": {
    "dev":   "vinext dev",    // 原本 next dev
    "build": "vinext build",  // 原本 next build
    "start": "vinext start"   // 原本 next start
  }
}
```

已支援的功能覆蓋率約 94%，以下是 App Router 路由支援對照：

```
app/
├── page.tsx           → / 首頁（完全支援）
├── layout.tsx         → 全域 Layout（完全支援）
├── loading.tsx        → 載入 UI（完全支援）
├── api/
│   └── route.ts       → API route handler（完全支援）
└── [id]/
    └── page.tsx       → 動態路由（完全支援）
```

目前是 Experimental 狀態，主要缺口在較新的 App Router 功能（如 Partial Prerendering）。Cloudflare 開源此工具的動機是降低遷移摩擦：先用熟悉的 Next.js 開發，之後評估是否移轉到 Cloudflare Workers 部署時不需要重寫整個 App。

📖 [github.com/cloudflare/vinext](https://github.com/cloudflare/vinext) ｜ 2026 年（確切發布日期未確認）｜ 開放搜尋補充

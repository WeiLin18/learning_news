1. **[Framework][React][編譯器][工程知識] Octane：把 React 的程式設計模型完全編譯掉**
   Octane 是 Inferno 作者 Dominic Gannaway（也是 React 前核心貢獻者之一）推出的新框架，定位是「Inferno 的精神續作」：保留 React 熟悉的 JSX/hooks 寫法，但完全不用 virtual DOM，也不需要手動維護 dependency array 或遵守 Rules of Hooks——編譯器會靜態分析閉包捕獲的變數，自動產生對應的 DOM 更新指令。範例：
   ```jsx
   import { useState } from 'octane';
   export function Counter() {
     const [count, setCount] = useState(0);
     return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
   }
   ```
   這段程式碼看起來跟 React 完全一樣，但 Octane 編譯後直接產生 DOM 操作，沒有執行期 diff 開銷；還提供 `.tsrx` 語法糖（內建 `@if`/`@for`/`@switch` 指令）與串流 SSR。目前為 alpha 版，987 star、3,900+ 行為測試，對想理解「React 心智模型」還能被推向多激進的編譯優化的工程師是很好的參考案例。
   來源：GitHub（直接開啟驗證）｜https://github.com/octanejs/octane（Hacker News 討論串亦提及，開放搜尋補充）
   發布日期：專案於 2026-07-27 前後開始受討論（近期，約 1 週前）

   TanStack Start 本身並未移除 RSC 支援，這只是 tanstack.com 這個網站自己的選擇——是一篇很好的「RSC 該是可選能力、不該是預設中心架構」提醒文，對正評估要不要導入 RSC 的團隊很有參考價值。

6. **[Blog][AI輔助開發] Addy Osmani — Software Factories, Light and Dark**
   Addy Osmani 提出「軟體工廠」的比喻：AI 輔助開發正從「寫程式碼」轉變成「設計並營運一整套自動化迴圈（loop）」——一個 loop 反覆做「收集脈絡 → 實作 → 驗證 → 改善」。他把「工廠」分成「光明」與「黑暗」兩種：黑暗工廠讓程式碼在無人閱讀、只靠機器互相驗證下就上線；光明工廠則把人類判斷力前移到設計與架構階段，而不是留到最後才審一次。核心主張是「背壓（back pressure）」：一個 loop 能拿到多少自主權，取決於你能多快、多可靠地驗證它的產出，而不是它能吐出多少程式碼。範例情境：
   ```
   黑暗工廠：AI 產出 → 直接合併 → 出事才回頭查
   光明工廠：AI 產出 → 先過測試/型別/lint 關卡 → 人類抽查關鍵決策點 → 才合併
   ```
   對正在把 Claude Code / Cursor 等 coding agent 導入團隊、思考「該給多少自主權」的工程主管很有參考價值。
   來源：Addy Osmani 個人部落格（AGENTS.md 指定名單內的工程師，開放搜尋補充）｜https://addyosmani.com/blog/software-factories/

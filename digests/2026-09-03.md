### 1. Vue 3.6 Vapor Mode：告別 Virtual DOM，效能貼近 SolidJS

Vue 3.6 引入 **Vapor Mode**，讓編譯器可以直接產生精細的 DOM 操作指令，完全跳過 Virtual DOM 的 diff 計算。官方 benchmark 顯示，掛載 10 萬個元件只需約 100ms，與 SolidJS 幾乎持平，比 Vue 3.5 標準模式（約 240ms）快了一倍以上。

Vapor Mode 最大的亮點是**語法完全向下相容**：只需在 `<script setup>` 加上 `vapor` 屬性，既有的 Composition API 邏輯不需改寫，Vapor 與標準元件也可以混用在同一個 app 裡。這對既想保有現有程式碼、又想讓關鍵路徑提速的大型專案特別友善。

```vue
<!-- 標準 Vue 3（語法不變） -->
<script setup>
import { ref, computed } from 'vue'
const count = ref(0)
const doubled = computed(() => count.value * 2)
</script>

<!-- Vapor Mode：加上 vapor 屬性即啟用，編譯出 fine-grained DOM 更新 -->
<script setup vapor>
import { ref, computed } from 'vue'
const count = ref(0)
const doubled = computed(() => count.value * 2)
</script>

<template>
  <button @click="count++">{{ count }} × 2 = {{ doubled }}</button>
</template>
```

另一個實用細節：Vapor 元件在 Vue DevTools 中仍然可以正常 inspect，完全保留 Vue 的開發體驗。對已踏入 Vue 生態但覺得效能不夠的團隊來說，這是可以直接動手試的升級路徑。

### 2. Next.js 16.3：Instant Navigations，SPA 感的頁面切換來了

Next.js 16.3 的核心功能是 **Instant Navigations**：頁面之間的切換在感知上接近 SPA，即使在慢速網路下也幾乎感受不到延遲。實現方式是**局部預取（Partial Prefetch）**——只預取下一頁「真正改變」的 segment，而不是整頁，大幅降低預取的資料量。同版本的 Turbopack 記憶體用量降低 90%，讓 dev server 體驗也同步改善。

從開發者視角看，大部分情況下**不需要手動調整**，行為由框架自動管理。`<Link>` 元件在進入 viewport 時自動觸發局部預取；若有需要也可以明確控制 `prefetch` 行為。

```jsx
// 預設行為：進入 viewport 自動局部預取
<Link href="/dashboard">儀表板</Link>

// 強制完整預取（適合已知使用者一定會點的連結）
<Link href="/checkout" prefetch={true}>結帳</Link>

// 停用預取（適合登入後才能進入的頁面，避免資料外洩）
<Link href="/admin" prefetch={false}>後台管理</Link>
```

這個版本的 Turbopack 也正式支援生產環境 build（之前只有 dev 可用），代表從本機開發到部署都能用同一套工具鏈，減少「dev 跑得好、prod build 卻有問題」的情況。

### 4. taste-skill：給 AI coding agent 注入前端設計品味（GitHub Trending）

### 7. impeccable：讓 AI 停止生成「slop」設計的規範語言

「AI slop」在設計圈指的是那種「看起來很 AI 生成」的 UI——每個按鈕都圓角、每個卡片都有一模一樣的陰影、每段文字都 line-height 1.8、每個動畫都 fade-in 0.3s。**impeccable** 是一套設計語言規範，搭配 1 個 Claude Code skill、23 個 slash command 和 **61 條確定性偵測規則**，系統化地阻止 AI 產出這類設計。

它的設計哲學是：與其讓人逐一 review AI 的設計決策，不如用規則讓 AI 在生成時就自我約束。61 條規則是確定性的（deterministic），不是靠 AI 判斷「好不好看」，而是明確定義哪些 pattern 是被禁止的。

```yaml
# .impeccable.yml — 放在專案根目錄，agent 自動讀取

typography:
  scale: [12, 14, 16, 20, 24, 32, 48]  # 只允許這幾個字型大小（px）
  min-contrast: 4.5                     # 正文最低對比度（WCAG AA）
  max-weights: 2                        # 整個頁面最多只用兩種字重

spacing:
  grid: 4px          # 所有 margin/padding 必須是 4 的倍數
  max-nesting: 3     # CSS class 巢狀最多三層

motion:
  prefer-native: true         # 優先 CSS transition，不用 JS 動畫框架
  max-duration: 300ms         # 動畫不超過 0.3 秒
  forbidden: ["bounce", "elastic"]  # 禁止這兩類緩動函式

borders:
  max-radius-variants: 2    # 整個 UI 最多只能有 2 種圓角值

# 違反規則時，/impeccable-check 會列出具體違規位置
# 例如："Button.tsx:47 — border-radius: 12px 不在允許清單 [4px, 8px]"
```

### 8. Vite 7.0：預設目標轉向 Baseline，Node.js 18 正式退場

Vite 7.0 帶來兩個重大預設值變更。首先，**最低 Node.js 版本提升至 20.19+**（或 22.12+），Node.js 18 在此版本正式不再支援。其次，**預設的瀏覽器目標從 `modules` 改為 `baseline-widely-available`**——只輸出在近 30 個月內所有主流瀏覽器（Chrome、Firefox、Safari、Edge）都已支援的功能，不再假設「支援 ES Module = 所有現代 API 都有」。

從實際遷移角度看，大多數專案只需要確認 Node.js 版本，以及檢查是否有依賴非常新的瀏覽器 API。對 `target` 的改變影響的是 `vite build` 的輸出，dev server 行為不變。

```js
// vite.config.js — 升級後的常見調整

export default defineConfig({
  build: {
    // Vite 7 預設：'baseline-widely-available'
    // 輸出只使用 ~30 個月內所有主流瀏覽器都支援的語法

    // 若需要支援更新的 API（如 Array.fromAsync），明確指定：
    target: 'esnext',

    // 或保留 Vite 6 的舊行為：
    target: 'modules',
    // 'modules' = 支援 ES Module 的瀏覽器（範圍比 baseline 廣一點）
  }
})
```

```bash
# 快速確認升級後 build 輸出的差異
npx vite@7 build --debug 2>&1 | grep "target"
# 輸出範例：
# [vite] build target: baseline-widely-available
# [vite] transformed 124 modules in 1.2s
```

另一個重要穩定化：實驗性的 **Environment API**（Vite 6 引入）在 Vite 7 正式穩定，讓 SSR、Node、Edge runtime 共用同一套 Vite 設定時更有彈性，對 Next.js、SvelteKit、Remix 等框架的底層整合影響較大。

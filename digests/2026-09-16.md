### 1. 同一張表，兩套框架：TanStack Table v9.2.4 在 React 19.3 vs Vue 3.5 的實作差異

`[工程知識]` `[React]` `[Vue]` `[TanStack]` `[框架比較]`

TanStack Table v9.2.4 在 8 月 28 日同步釋出所有 adapter 的穩定版，這篇文章就用「一張有排序、篩選、分頁功能的資料表」作為載體，讓 React 19.3 與 Vue 3.5 的實作排排站：從 `useReactTable` 對上 `useVueTable`，到 `state` 的傳入方式，清楚呈現兩套框架在「狀態管理整合方式」上的根本差異。

React 版需要把 state（sorting、columnFilters、pagination）以 getter 形式傳入，再搭配各自的 `onChange` 回呼；Vue 版則用 `computed()` 包住所有 state，讓 reactive 自動追蹤更新，不需要手動的 onChange。文章說這是兩個框架設計哲學的縮影：React 偏顯式、Vue 偏隱式。

**範例一（React 19.3 的 state 傳入方式）**：

```tsx
import { useReactTable, getCoreRowModel, getSortedRowModel,
         getFilteredRowModel, getPaginationRowModel } from '@tanstack/react-table';

const [sorting, setSorting] = useState<SortingState>([]);
const [columnFilters, setColumnFilters] = useState<ColumnFiltersState>([]);

const table = useReactTable({
  data,
  columns,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),
  getFilteredRowModel: getFilteredRowModel(),
  getPaginationRowModel: getPaginationRowModel(),
  // React：state 用物件傳入，onChange 單獨設定
  state: { sorting, columnFilters },
  onSortingChange: setSorting,
  onColumnFiltersChange: setColumnFilters,
});
```

**範例二（Vue 3.5 的 computed state 寫法）**：

```vue
<script setup>
import { ref, computed } from 'vue';
import { useVueTable, getCoreRowModel, getSortedRowModel } from '@tanstack/vue-table';

const sorting = ref([]);
const columnFilters = ref([]);

const table = useVueTable({
  get data() { return props.data },   // getter 讓 Vue reactivity 追蹤
  columns,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),
  // Vue：state 和 onChange 都打包進 computed 的 getter/setter
  state: computed(() => ({ sorting: sorting.value, columnFilters: columnFilters.value })),
  onSortingChange: (updater) => { sorting.value = updater(sorting.value) },
  onColumnFiltersChange: (updater) => { columnFilters.value = updater(columnFilters.value) },
});
</script>
```

### 2. OpenHands 1.0 正式釋出：不交出 API 金鑰也能自架的 AI Coding Agent

`[工程知識]` `[AI 輔助開發]` `[自架]` `[教學]`

開源 AI Coding Agent OpenHands 發布了 1.0 版，帶來生產就緒的 Docker Sandbox 隔離層、內建安全策略、資源限制、Plugin 系統，以及在 SWE-bench Verified 基準上 68% 的自主完成率（Devstral 24B 模型可達 46.8%，與 Devin 2.0 持平）。這篇 DEV Community 文章的核心是「如何在自己的機器上跑 OpenHands，而不把你的 Anthropic/OpenAI API 金鑰交給第三方服務」。

關鍵做法是用 Docker Compose 在本機跑一個完整的 OpenHands 堆疊：LLM proxy、sandbox runtime、task runner 全部跑在你自己的環境裡。AI Agent 在 sandbox 容器內執行 shell 指令和寫程式，主機的 API 金鑰只在 proxy 層被使用，sandbox 本身完全隔離。以 H100 GPU 費率估算，每個解決的 task 約花 $0.20—$1.05 美元（自帶模型的情況）。

**範例一（最快啟動：Docker 一行指令）**：

```bash
# 自架 OpenHands 1.0（需要 Docker）
docker run -it --pull=always \
  -e SANDBOX_RUNTIME_CONTAINER_IMAGE=docker.all-hands.dev/all-hands-ai/runtime:0.41-nikolaik \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v ~/.openhands-state:/.openhands-state \
  -p 3000:3000 \
  --add-host host.docker.internal:host-gateway \
  docker.all-hands.dev/all-hands-ai/openhands:latest
# 完成後瀏覽器開 http://localhost:3000，輸入你的 API 金鑰即可使用
```

**範例二（Plugin 系統：給 Agent 掛上自訂工具）**：

```yaml
# .openhands/config.yaml
plugins:
  - name: figma-mcp
    type: mcp_server
    command: npx @figma/mcp-server
    env:
      FIGMA_TOKEN: "${FIGMA_TOKEN}"   # 從環境變數注入，不寫死
  - name: linear-integration
    type: mcp_server
    command: npx @linear/mcp-server
# Agent 啟動時自動掛載，可讀取 Figma 設計稿或更新 Linear 任務
```

### 3. context-mode：MCP Server 讓 AI Coding Agent 的 Context 用量縮減 98%

`[工程知識]` `[AI 輔助開發]` `[MCP]` `[Context 優化]`

`mksglu/context-mode` 解決了 AI Coding Agent 在處理大型 codebase 時的「context 爆炸」問題：「每次 MCP 工具呼叫都把原始資料塞進 context——一份 Playwright snapshot 56 KB，二十個 GitHub issues 59 KB，很快就把 context window 填滿。」這個 MCP Server 提供四個機制：工具輸出沙箱化（agent 產生 script 分析資料，只把結果輸出進 context）、SQLite 的 session 跨對話持久記憶、BM25+三元組的全文搜尋，以及 MCP hook 路由（攔截高流量工具呼叫，導向沙箱執行）。

它提供 11 個 MCP 工具，其中最關鍵的是 `ctx_execute`：Agent 不再讀取數十個原始檔案，而是生成一小段 JavaScript/Python/Shell script，沙箱執行後只把數字或結構化輸出送回 context，效果是「315 KB 變 5.4 KB，縮減 98%」。支援 Claude Code、Cursor、GitHub Copilot CLI、VS Code Copilot 等 17 個平台。

**範例一（before/after：讀 47 個 TypeScript 檔案）**：

```javascript
// Before：47 × Read() = 700 KB 塞進 context
// Agent 要把每個 .ts 檔案全文讀進來才能分析行數

// After：1 × ctx_execute() = 3.6 KB
ctx_execute("javascript", `
  const fs = require('fs');
  // 在沙箱內執行，只輸出分析結果
  const files = fs.readdirSync('src').filter(f => f.endsWith('.ts'));
  files.forEach(f => {
    const lines = fs.readFileSync('src/' + f, 'utf8').split('\\n').length;
    console.log(f + ': ' + lines + ' lines');
  });
  // 輸出：Button.ts: 112 lines、Modal.ts: 247 lines...
  // 總共 3.6 KB，而非 700 KB
`);
```

**範例二（ctx_fetch_and_index：把文件 URL 快取成可搜尋的向量）**：

```javascript
// 把 Next.js 文件抓下來，切塊快取（24 小時 TTL）
ctx_fetch_and_index("https://nextjs.org/docs/app/api-reference/functions/use-router", {
  ttl: 86400   // 秒
});

// 之後搜尋，不用再 fetch；BM25 + Porter stemming 找相關段落
ctx_search("useRouter navigation replace vs push");
// 只回傳最相關的幾段，而非整份文件
```

### 4. alibaba/open-code-review：阿里巴巴內部磨了兩年、服務過數萬開發者的 AI Code Review CLI

`[GitHub Trending]` `[AI 輔助開發]` `[Code Review]` `[TypeScript]`

`alibaba/open-code-review` 是阿里巴巴內部使用了兩年後才開源的 AI Code Review 工具，號稱「已在生產環境識別出數百萬個程式缺陷」。架構採「確定性管線 + LLM Agent」混合模式：確定性部分負責精確選取需要 review 的檔案（不漏、不多）、把相關檔案打包給 Agent；Agent 部分負責動態拉取 repo 脈絡、生成精確到行號的評論。支援 JavaScript、TypeScript、Python、Go 等 10 種語言，以及 OpenAI 與 Anthropic 的所有主流模型，目前在 GitHub Trending TypeScript 榜佔據第一位（11,801 stars，9 月 14-15 日）。

內建 ruleset 覆蓋 NPE、thread-safety、XSS、SQL injection 等常見漏洞類型，對 React/Node.js 前端棧特別有用：它能在 PR 裡直接指出 `dangerouslySetInnerHTML` 的 XSS 風險位置，並給出修正建議，而不只是泛泛說「這裡有 XSS」。

**範例一（CLI 基本用法）**：

```bash
# 安裝
npm install -g @alibaba/open-code-review

# 對最近一次 git commit 執行 code review
ocr review

# 指定 LLM provider
ocr review --provider anthropic --model claude-opus-5

# 只 review 特定目錄
ocr review --include "src/components/**"
```

**範例二（掃描整個 codebase 找 XSS）**：

```bash
# 全 repo 掃描模式（不只看 diff，而是全量分析）
ocr scan ./src --lang javascript,typescript

# 輸出格式（JSON，方便整合 CI/AI pipeline）
ocr review --output json | jq '.findings[] | select(.severity == "HIGH")'
# → { "file": "UserProfile.tsx", "line": 42,
#     "message": "dangerouslySetInnerHTML 的 value 來自 user.bio，
#                 未經 sanitize，存在 XSS 風險",
#     "suggestion": "使用 DOMPurify.sanitize(user.bio)" }
```

### 6. Chrome 154 Beta：scroll-marker-group 新增 tabs 無障礙模式，以及 Private Verification Tokens

`[前端技術棧]` `[Chrome]` `[Web 平台]` `[CSS]` `[安全性]`

Chrome 154 Beta（2026-09-02 釋出，預計 9 月 22 日穩定版）帶來兩個值得關注的 Web 平台更新。`scroll-marker-group` 新增 `tabs` 值：過去這個屬性只有 `auto`/`before`/`after`，讓 scroll snap container 自動生成輔助點（bullet dots）；`tabs` 模式會自動為 marker group 加上 `role="tablist"`，為每個 marker 加上 `role="tab"`，使這些 scroll 指示點在語意上成為真正的 Tab 導覽介面，螢幕閱讀器能正確宣告「選了第幾個 Tab」。另一個新功能是 **Private Verification Tokens（PVT）**，讓使用者在一般瀏覽模式建立的「不是機器人」信任憑證，能安全地轉移到無痕模式，減少無痕瀏覽時一直被要求通過 CAPTCHA 的困擾。

`scroll-marker-group: tabs` 對常見的「圖片輪播 + 圓點導覽」場景影響很大：過去前端工程師要額外寫 ARIA 屬性才能讓輔助技術正確理解；現在只要把 `links`（預設）改成 `tabs`，瀏覽器自動處理語意和鍵盤操作。

**範例一（scroll-marker-group 兩種模式對比）**：

```css
/* links 模式（預設）：語意是「導覽連結清單」*/
.carousel {
  scroll-snap-type: x mandatory;
  overflow-x: scroll;
  scroll-marker-group: auto; /* 預設就是 links 模式 */
}

/* tabs 模式：語意是「Tab 面板切換」，適合輪播 */
.carousel {
  scroll-snap-type: x mandatory;
  overflow-x: scroll;
  scroll-marker-group: tabs; /* ← 新增 */
  /* 瀏覽器自動加：
     ::scroll-marker-group { role: "tablist" }
     .carousel > *::scroll-marker { role: "tab" } */
}

.carousel::scroll-marker-group {
  display: flex;
  gap: 8px;
  justify-content: center;
}
```

**範例二（PVT 使用情境：無痕模式下免 CAPTCHA）**：

```
使用者在一般瀏覽模式：
  → 通過 Google reCAPTCHA，網站頒發 PVT Token
  → Token 用 Privacy Pass 協議加密保存（無法追蹤身份）

使用者切換到無痕模式，造訪同一網站：
  → 瀏覽器提示：「是否使用先前的驗證信任？」
  → 使用者同意 → PVT Token 轉移，跳過 CAPTCHA
  → 整個過程網站看不到使用者身份，只知道「這個瀏覽器有效的 token」
```

### 8. GitHub Copilot CLI 9 月 12 日更新：session import / memory import 與 Shell Completion 全面強化

`[前端技術棧]` `[AI 工具]` `[GitHub Copilot]` `[CLI]`

GitHub Copilot CLI 在 9 月 12 日的更新中，新增了兩個在 AI 輔助開發流程裡很實用的指令：`session import`（從 JSONL 文件恢復先前對話 session）與 `memory import`（載入跨 session 的記憶快照），兩者都採用語意化的 JSONL 格式，能和其他 AI 工具互換。這讓「我昨天在 Copilot CLI 裡做的 refactoring 討論」可以被打包後在新的 session 繼續，或甚至匯出給其他 AI 工具閱讀。同批更新也大幅改善了 shell completion（zsh、fish、bash 皆支援），讓 `gh copilot suggest`、`gh copilot explain`、`gh copilot review` 等指令有完整的 tab-completion 提示，包含旗標和常用參數。

此外，sandbox 隔離行為、MCP 工具呼叫、串流輸出、子 agent 協調、用量回報以及遠端 session 管理都有細部調整。對習慣在 terminal 工作的前端工程師，這次更新讓 Copilot CLI 更接近一個有記憶、能跨天繼續作業的 AI 開發夥伴，而不只是一個問答機器。

**範例一（session import/export 流程）**：

```bash
# 上次的 session 結束前，先匯出
gh copilot session export ./refactor-auth-2026-09-15.jsonl

# 隔天，新 session 繼續
gh copilot session import ./refactor-auth-2026-09-15.jsonl
# → Copilot 會讀取昨天的對話紀錄，直接繼續上次的任務
# → 適合長跨度的 refactoring 或多天的功能開發
```

**範例二（啟用 shell completion，讓 tab-complete 提示旗標）**：

```bash
# zsh：在 ~/.zshrc 加入
eval "$(gh copilot completion zsh)"

# fish：
gh copilot completion fish | source

# bash：
eval "$(gh copilot completion bash)"

# 之後在 terminal：
# gh copilot suggest --<Tab>
# → --target (shell) --shell-out --model --provider ...
# gh copilot review --<Tab>
# → --file --diff-from --output-format ...
```

### 1. Creating Web Widgets Using the Document Picture-in-Picture API

`[工程知識]` `[Web API]` `[Browser]`

Document Picture-in-Picture API 讓你把**任意 HTML 元素**（不只是影片）放進一個浮動的小視窗，使用者切換分頁後它還在畫面上。Firefox 151 在今年稍早正式出船，這篇 CSS-Tricks 教學從 `window.documentPictureInPicture.requestWindow()` 開始，帶你完整建一個可互動的浮動 Widget。

最基本的啟動只需要幾行：

```js
// 開啟一個 300×200 的浮動視窗
const pipWindow = await window.documentPictureInPicture.requestWindow({
  width: 300,
  height: 200,
});

// 把你的 DOM 元素移進去（原頁面上會消失，PiP 視窗裡會出現）
pipWindow.document.body.appendChild(myWidget);
```

實際使用情境：Pomodoro 計時器、會議中的即時筆記欄、音樂播放控制列——原本要靠系統層的桌面 Widget，現在純 Web 就能做。CSS 樣式、事件監聽都跟一般 DOM 一樣，不需要學新語法。

### 2. React Compiler Memoization: What Actually Broke

`[工程知識]` `[React]` `[實務踩坑]`

React Compiler 號稱「自動 memo 全部元件」，這篇 LogRocket 文章記錄了真實專案啟用後踩到的坑：Compiler 假設函式是純的，但有幾種 pattern 會悄悄破壞這個假設——最常見的是在 render 中直接讀寫 `ref.current`，以及閉包裡抓到舊 state。

**Before / After 對比（最常見的 ref 問題）**：

```jsx
// ❌ 在 render 裡直接改 ref.current，Compiler 追蹤不到這個副作用
function Counter({ onUpdate }) {
  const countRef = useRef(0);
  countRef.current += 1;        // 每次 render 都改，Compiler 以為元件是純的
  return <div>{countRef.current}</div>;
}

// ✅ 把狀態移回 useState，副作用放進 useEffect
function Counter({ onUpdate }) {
  const [count, setCount] = useState(0);
  useEffect(() => { onUpdate(count); }, [count, onUpdate]);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

文章也示範了 Compiler 附帶的 ESLint plugin 輸出——啟用後在 CI 階段就能抓到這類問題，不用等到 runtime 才發現畫面卡住或資料錯亂。

適合已經在評估或剛啟用 React Compiler 的團隊，特別是有大量 `ref` 操作或複雜閉包的既有 codebase。

### 3. Reliable Query Prefetching with TanStack Router

`[工程知識]` `[React]` `[TanStack]` `[效能]`

TanStack Router 的 route loader 可以在使用者進入頁面前就預先抓資料，但「等 prefetch 完才渲染」和「邊渲染邊 stream」哪個好？這篇由 TanStack Query 核心維護者 Dominik Dorfmeister（TkDodo）撰寫的文章，把兩種策略的 trade-off 講得很清楚。

**策略一：`await` loader（等完再渲，適合首次進入）**

```ts
// route.ts — 進頁面前就把資料抓好，元件一掛載就有資料，沒有 loading 閃爍
export const loader = async ({ context: { queryClient } }) => {
  await queryClient.ensureQueryData(postsQueryOptions);
};
```

**策略二：`prefetch` 不 await（邊走邊抓，適合 tab 切換）**

```ts
// route.ts — 只發請求，不等它完成；元件用 Suspense 等，不阻塞 UI
export const loader = ({ context: { queryClient } }) => {
  queryClient.prefetchQuery(postsQueryOptions);  // 沒有 await
};
```

結論：首次進入頁面用 `await`（SEO 友善、Loading 指示器好控制），同一頁面的 tab 切換用 `prefetch`（使用者不感覺到頁面凍住）。文章也講了 SSR 情境下兩種方式各自的陷阱。

### 4. oh-my-pi — 把 IDE 語意直接接進 AI 代理的開發工具

`[GitHub Trending]` `[AI輔助開發]` `[DX工具]`

oh-my-pi 是一個把 Language Server Protocol（LSP）跟 AI 代理串在一起的 TypeScript 工具，讓 LLM 在修改你的程式碼時能「真的看懂」型別、定義、引用——而不只是把整個檔案當成純文字貼給它。支援 40+ 個 LLM 供應商，內建 32 個工具（git、terminal、網路請求等），還有 AI 自動填寫 commit message。

安裝與啟動：

```bash
npm install -g oh-my-pi
# 在你的專案根目錄執行，會自動連接本地的 LSP server
ompi
```

跟「把整個檔案貼給 LLM 看」的傳統方式不同，oh-my-pi 讓 AI 能主動問「`getUserById` 的回傳型別是什麼？」——類似 Cursor 的 codebase-aware 模式，但可以接你自己的 LLM API key，不需要鎖定特定 IDE。

### 5. TanStack AI 進入 RC 階段，拿下 2026 Open Source Awards

`[AI輔助開發]` `[前端技術棧]` `[TanStack]`

TanStack AI 在 8 月 21 日進入 Release Candidate，並在 2026 Open Source Awards 拿下「AI Project of the Year」。它把 24 個 AI 供應商（OpenAI、Anthropic、Gemini……）統一包裝成一套前端友善的 API，支援串流對話、媒體生成、MCP 工具調用，以及讓 AI 在沙盒裡執行程式碼後看結果再修正。

最小化串流對話範例：

```ts
import { useChat } from '@tanstack/react-ai';

function ChatBox() {
  const { messages, sendMessage } = useChat({
    provider: 'anthropic',
    model: 'claude-opus-5',
  });

  return (
    <>
      {messages.map(m => <p key={m.id}>{m.content}</p>)}
      <button onClick={() => sendMessage('Hello!')}>Send</button>
    </>
  );
}
```

跟 Vercel AI SDK 最大的差別是它直接整合 AG-UI 協定（讓 AI 能操作你的 React 元件狀態），以及內建執行沙盒——AI 不只給你程式碼，它還能跑程式碼、看結果、自我修正後再回傳。

### 6. Effect v4 RC — Bundle 縮水 70%、速度提升 65%

`[前端技術棧]` `[TypeScript]` `[函式庫]`

Effect 是一套把「錯誤處理、非同步、依賴注入、追蹤」整合進同一個型別安全 pipeline 的 TypeScript 函式庫。v4 RC（8 月 13 日）的重點是全新重寫的執行時期：Bundle size 從 70KB 降到 20KB，執行速度提升 65%，並大幅簡化依賴注入的寫法。

試用只需要一行：

```bash
npm install effect@rc
```

Before / After 對比——原本需要手動串接每一層依賴的樣板程式碼：

```ts
// v3：手動 .provide() 每一層，且順序不能錯
const program = pipe(
  getUser(userId),
  Effect.provide(UserService.Default),
  Effect.provide(DatabaseLayer),
);

// v4 RC：依賴自動解析，直接 runPromise
const program = getUser(userId);
await Effect.runPromise(program);  // Effect 自己找到需要的 layer
```

如果你之前覺得 Effect 的 bundle 太重沒辦法在 browser 端用，v4 的 20KB 應該值得重新評估——尤其是搭配 tree-shaking 後實際引入的量還會更少。

### 7. Chrome 正式切換到兩週發布週期

`[Web平台]` `[Browser]`

Chrome 153（預計 9 月 8 日推出）起，Chrome 的發布週期從四週縮短為兩週。每個版本帶的功能變少、每個功能從進主幹到出貨的等待時間縮短，安全性修補也能更快送到用戶手上。Chrome for Developers 官方公告解釋了背後考量與對開發者的影響。

對前端工程師最直接的兩個影響：

1. **Origin Trial 測試窗口縮短**：以前有四週可以驗證新 API，現在只有兩週，需要更快決定要不要 opt-in。
2. **版本號更新更快**：如果程式碼裡有 UA sniffing（強烈不建議），版本跳得更頻繁要特別注意。

小型功能受益最大——一個小的 CSS/JS API 提案以前要等數個月才出貨，現在可以更快讓使用者用到。PR #25 中 CSS Wizardry 的文章從 RUM 效能監控的角度分析了這個改變的影響，可以搭配一起看。

### 8. TypeScript 5.9 正式發布 — import defer、穩定的 --module node20

`[前端技術棧]` `[TypeScript]`

TypeScript 5.9 在 8 月 1 日釋出，最受關注的新特性是 **`import defer`**：延遲執行模組（及其所有依賴）的初始化，直到你第一次存取它的 export 才真正跑。這對啟動效能很有幫助——bundle 大小不變，但 main thread 一開始不需要初始化那麼多東西。

```ts
// import defer：import 時不執行，直到真正用到時才初始化
import defer * as heavyLib from './heavy-lib';

console.log('app starting...');  // 這時 heavy-lib.ts 還沒跑

// 直到使用者點按鈕，heavy-lib.ts 才真的被執行和初始化
button.addEventListener('click', () => heavyLib.doSomething());
```

另一個值得注意的是 `--module node20`：鎖定 Node.js v20 的模組解析行為（不會因為 Node 升版而改變），是 `--moduleResolution nodenext` 的穩定版。如果你的 CLI 工具一直出現 `Cannot find module` 的 ESM 錯誤，換成 `--module node20` 通常能解決：

```json
// tsconfig.json
{
  "compilerOptions": {
    "module": "node20",   // 以前寫 "nodenext"，行為一樣但這個不會隨 Node 版本飄移
    "target": "es2023"    // node20 會自動推論這個，不用重複寫
  }
}
```

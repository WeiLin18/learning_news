### 1. Chrome Modern Web Guidance：防止 AI Coding Agent 寫出老舊前端程式碼

`[工程知識]` `[AI輔助開發]` `[DX工具]`

Google Chrome 團隊發表 Modern Web Guidance——一份含 128 條現代 Web 最佳實踐的 Apache 2.0 技能包，專門設計給 AI coding agent 安裝使用。裝了之後，AI agent 就不會再用 jQuery 做動畫（CSS 可以做）、用 `<div tabindex>` 代替語意化的 `<button>`，或呼叫已被 deprecated 的 API。

在 Claude Code 裡安裝只需要一行：

```bash
# 方式一：用 npx 安裝到任何支援 MCP 的 AI coding agent
npx modern-web-guidance@latest install

# 方式二：Claude Code 的 plugin marketplace 直接加
/plugin marketplace add GoogleChrome/modern-web-guidance
```

Google 自己的測試顯示，安裝後 AI agent 寫出的程式碼符合 Web 最佳實踐的比率提升了 37 個百分點。128 條規則涵蓋 HTML 語意化、CSS 現代特性、Performance API、安全的 fetch 模式等。

適合每天用 AI coding agent 開發的前端工程師，直接裝進你的 agent 設定。若你在意 AI 幫你寫出的程式碼「夠不夠現代」，這包比手動 review 有效率得多。

### 2. Smashing Newsletter #581：2026 年還需要 JavaScript 打包工具嗎？

`[工程知識]` `[建置工具]` `[JavaScript]`

這期 Smashing Newsletter 收錄兩篇互補的技術文章。Ollie Williams 問了一個很多人沒認真想過的問題：在瀏覽器原生支援 ES modules、import maps 越來越普及的 2026 年，Webpack/Vite 這類打包工具還有存在的理由嗎？答案是「大部分場合還是需要，但理由跟以前不一樣了」——重點從「讓舊瀏覽器跑 ES6」轉移到「tree-shaking、code splitting、asset pipeline 整合」。

Paweł Grzybek 整理了 ECMAScript 2026 的新特性，幾個實用例子：

```js
// 1. Array.groupBy（終於標準化）
const result = Array.groupBy([1, 2, 3, 4], n => n % 2 === 0 ? 'even' : 'odd');
// → { odd: [1, 3], even: [2, 4] }

// 2. Promise.try — 統一同步/非同步錯誤處理
// 就算 JSON.parse 丟出同步 Error，也能用 .catch 接，不用再包 try/catch
Promise.try(() => JSON.parse(input))
  .then(data => use(data))
  .catch(err => handleError(err));

// 3. RegExp duplicate named capture groups（同名群組可出現在不同分支）
const re = /(?<year>\d{4})-(?<month>\d{2})|(?<month>\d{2})\/(?<year>\d{4})/;
```

兩篇一起讀可以拼出一張 2026 年 JavaScript 工具鏈的全景圖：語言本身越來越強，打包工具的定位也在跟著進化。

### 3. React Compiler 2026：哪些情況會被自動 memo、哪些不會

`[工程知識]` `[React]` `[補收]`

React Compiler（以前叫 React Forget）穩定版和大家期待的不太一樣——它不是「把所有東西都 memo 掉」的魔法棒，而是有一套明確的啟發式規則。這篇文章用反例把規則講清楚，讀完你就知道為什麼裝了 compiler 某些元件「還是重渲染」。

哪些情況**會**被 auto-memo：

```jsx
// ✅ 純函式元件，props 是原始型別或穩定參照
function Button({ label, onClick }) {
  return <button onClick={onClick}>{label}</button>;
  // ↑ compiler 可以確認輸入穩定，會自動 memo
}

// ✅ hook 裡的衍生值（compiler 能追蹤依賴）
function usePrice(items) {
  const total = items.reduce((acc, i) => acc + i.price, 0);  // 會被 memo
  return total;
}
```

哪些情況**不會**被 auto-memo：

```jsx
// ❌ 每次 render 都建新物件當 props（compiler 看到「不穩定」就放棄）
<Chart config={{ color: 'blue', size: 12 }} />
//        ↑ 物件字面量每次都是全新的，compiler 無法自動穩定它，要自己包 useMemo

// ❌ 元件內部有明顯 side effect（compiler 保守地假設有副作用，不 memo）
function Logger({ id }) {
  console.log('render', id);   // 這行讓 compiler 不敢 memo
  return <div>{id}</div>;
}
```

適合從「裝了 compiler 但效果不明顯」的困惑出發，想弄清楚哪裡要自己補 `useMemo` / `useCallback` 的 React 工程師。

### 4. TanStack Redact 0.2.0：同樣的 React 程式碼，Bundle 縮小 66%

`[前端技術棧]` `[React]` `[效能]` `[建置工具]`

TanStack Redact 是一個 drop-in React runtime 替換方案——你的 `import { useState } from 'react'` 一行都不用改，只要在 Vite 或 Next.js 加一個 plugin，就能把 React runtime bundle 從 69 KB（gzip）壓到 23 KB，縮小幅度 66.3%。

Vite 安裝只需兩步，app 程式碼完全不動：

```ts
// vite.config.ts — 加這一行就夠了
import { redact } from '@tanstack/redact/vite'
export default defineConfig({
  plugins: [redact()]   // plugin 負責在 build time 把 react 替換成 redact
})

// 你的元件完全不用改，繼續用標準 React API
import { useState, useEffect } from 'react'   // ← 這行不動

function Counter() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>
}
```

Before/After 對比：React 19.3.0 原版 gzip 約 **69,162 bytes**；Redact 預設模式約 **23,311 bytes**（省 ~46 KB）。代價是拿掉了 concurrent scheduling、time slicing 和可中斷渲染——適合不需要這些功能的資料展示或後台管理頁面。Next.js 版本用 `withRedact` 包 `nextConfig`，同樣不需要改元件程式碼。

### 5. React Native 0.88：Events 改用 W3C EventTarget API、支援 Variable Fonts

`[前端技術棧]` `[React Native]` `[Web平台標準]`

React Native 0.88 有兩個比較實質的改動。第一個是 event dispatching 的底層換成 W3C EventTarget API（以前是自己的事件系統），讓 RN 的事件行為跟 Web 更一致——原本在 Web 能跑的 event listener 邏輯，移植到 RN 時不用再特別轉譯。

API 層面無 breaking change，寫法跟之前相同：

```jsx
// 觸摸事件寫法不變，底層換了實作
<TouchableOpacity onPress={handlePress} onLongPress={handleLongPress}>
  <Text>按我</Text>
</TouchableOpacity>

// 新增：Animated 物件現在也支援 W3C 標準的 addEventListener 風格
animatedValue.addEventListener('change', (e) => {
  console.log(e.value);  // ← 標準 W3C EventTarget 事件物件格式
});
```

第二個改動是支援 Variable Fonts——同一個字型檔可以在 `fontWeight`、`fontStyle` 之間連續變化，不用引入多個字型檔，減少 bundle 大小的同時也讓 UI 動畫更流暢。升級路徑：Expo SDK 58 會把這個版本打包進去，Expo 用戶等 SDK 58 就好；非 Expo 用戶可以現在升 `react-native@0.88`。

### 6. cloudflare/security-audit-skill：給 AI Coding Agent 的多階段安全稽核技能包

`[GitHub Trending]` `[AI輔助開發]` `[安全]` `[DX工具]`

本週 GitHub Trending 增速最快的 repo（新增 11.9K stars，總計 56.3K），是 Cloudflare 開源的 AI agent 安全稽核技能包。概念跟 Chrome Modern Web Guidance 類似——也是掛進 AI coding agent 的技能包，但專注在安全層面：讓 agent 主動跑多階段安全稽核，而不是等你問才提。

掛進去後，AI agent 寫完一段功能就會自動跑三個階段：

```
Phase 1：靜態分析
  ├─ 掃描常見漏洞模式（SQL injection、XSS、path traversal…）
  ├─ 檢查 dependency 是否有已知 CVE
  └─ 標記 hardcoded credentials / secret

Phase 2：邏輯流程審查
  ├─ 追蹤使用者輸入如何流入敏感操作
  ├─ 確認 authentication / authorization 邊界
  └─ 找出 race condition 和 TOCTOU 問題

Phase 3：建議修正
  └─ 針對每個發現，出具附有可替換程式碼片段的修正建議
```

對前端工程師最直接的價值：讓 AI agent 在你叫它「寫個 API call / 資料處理」的時候，順手幫你想到 XSS sanitization、CSRF token、input validation 這些經常被遺漏的環節。

### 7. RSC 實戰指南 2026：正確模式、常見地雷、何時才該用 Server Component

`[前端技術棧]` `[React]` `[Next.js]` `[補收]`

React Server Components 推出一段時間了，但「到底哪些東西要用 Server Component、哪些不要」仍是讓很多人頭痛的問題。這篇文章不談理論，直接給出決策框架，並列出幾個在 Next.js App Router 裡最常被誤用的模式。

什麼情況適合用 Server Component（RSC）：

```tsx
// ✅ 資料層直接在 Server 跑，零 client-side fetch
// app/products/page.tsx
export default async function ProductsPage() {
  const products = await db.query('SELECT * FROM products LIMIT 20');
  // ↑ 直接呼叫 DB，不需要 useEffect + fetch，DB 連線不會暴露到 client
  return <ProductList products={products} />;
}
```

最常見的地雷——把帶有 state 的元件誤放在 Server Component 裡：

```tsx
// ❌ Server Component 不能有 state 或 event handler
export default function Counter() {        // 沒有 'use client'
  const [count, setCount] = useState(0);  // ← build time 就會報錯
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}

// ✅ 修正：加上 'use client' directive，讓這個元件在 client render
'use client';
export default function Counter() { /* ... */ }
```

何時**不要**用 RSC：需要即時互動（按鈕、表單、動畫）、需要存取瀏覽器 API（localStorage、geolocation）、或需要 WebSocket 的元件，都應該是 Client Component。這份指南最值得的是「決策樹」那部分，讀完後面對每個新元件都能快速判斷。

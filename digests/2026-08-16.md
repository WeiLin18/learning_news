### 1. Inside a TanStack Router Navigation

`[工程知識]` `[TanStack]` `[React]` `[框架]`

一次點擊連結，看起來只是「換頁」，實際上路由器要同時協調四件互相獨立、隨時可能被打斷的事：比對路由、跑 loader、決定何時顯示 pending UI、以及真的把畫面 render 出來。這篇拆解 TanStack Router 內部怎麼用 **lane（私有草稿）** 這個概念把它們解耦——每次導覽都先在一條私有 lane 上把結果組好，只有在它「仍然是目前這筆交易」時才准許發佈。

最好懂的類比是**餐廳出餐**：客人可以隨時改點（快速連點兩個連結），廚房已經開始做的第一份不會直接端出去覆蓋新的那份，而是先確認「這張單還是最新的嗎」再決定要不要出餐：

```
使用者點 /posts/1  → 開 lane A：比對路由 → 跑 loader → 準備發佈
使用者又點 /posts/2 → 開 lane B（lane A 立刻失去「目前交易」資格）
lane A 的 loader 慢一步回來 → 發現自己已經不是目前交易 → 直接丟棄，不發佈
                                （這就是為什麼不會出現「舊頁面蓋掉新頁面」）
```

另一個實用概念是 loader 的 **flight ＋ lease（租約）**：一個 loader 呼叫由「promise ＋ abort controller ＋ 租約計數」組成，preload 與實際導覽可以共用同一次呼叫，各自持有一份租約——所有租約都放掉才真的取消。這解釋了為什麼滑鼠 hover 觸發的預載不會在真正點擊時重跑一次。文章也提到 redirect 的處理是「丟棄自己的 lane、開一條新的導覽」而不是當成錯誤，以及 React 實際 commit 後才回一張 `ack:true` 的收據——沒 commit 就代表被更新的導覽取代了。

作者的總結很值得記：把「取消／被取代／發佈／渲染」這四個決策者分開，就避免掉了數十種它們互相干擾產生的 bug。對想理解現代路由器為什麼要做得這麼複雜的人，這是少見把內部機制講清楚的文章。

### 2. Your SPA Is Leaking Memory. Soak Test It

`[工程知識]` `[效能]` `[測試]` `[Playwright]`

大部分前端測試只跑一次流程就結束，所以「跑一次沒事、跑兩百次記憶體爆掉」這類洩漏永遠測不出來。作者提出的 **soak test（浸泡測試）** 很簡單：在同一個瀏覽器 context 裡把同一段使用者流程重複跑 200 次，比對前後的 DOM 節點數與事件監聽器數量。

關鍵在於**看什麼指標**——作者明確說不要看 heap size，因為它本來就會自然浮動、雜訊太大；要看的是這兩個穩定的計數：

```
先跑 5 次暖機 → 記錄基準線 → 再跑 195 次 → 比對

監聽器數量：after.listeners ≤ baseline.listeners   ← 抓「忘了 removeEventListener」
DOM 節點數：after.nodes < baseline.nodes + 100     ← 抓「被移除但還被變數抓著的 detached 節點」
```

取指標前要先強制觸發兩次 GC，否則量到的是還沒被回收的垃圾：

```js
async function getPageMetrics(client) {
  await client.send('HeapProfiler.collectGarbage');   // 連做兩次，確保該回收的都回收了
  await client.send('HeapProfiler.collectGarbage');
  const { metrics } = await client.send('Performance.getMetrics');
  return Object.fromEntries(metrics.map((m) => [m.name, m.value]));
}
```

另一個聰明的技巧是**把時間壓縮**：如果應用裡有每 15 秒跑一次的 polling，不用真的等一小時——mock 掉時鐘，每一輪推進 18 秒，200 輪就等於模擬了一小時的計時器行為。作者也把整套流程包成 `playwright-soak-test` 這個 npm 套件，可以直接接進 CI。

📖 [denodell.com](https://denodell.com/blog/your-spa-is-leaking-memory-soak-test-it) ｜ 2026-07-29（**較早，約 2.5 週前——已超出 Step 4 的兩週時間窗**，因本輪新內容不足而納入，照實標註）｜ 優先來源（Frontend Focus #754）

### 3. JavaScript Memory Management & Garbage Collection Explained: V8 Internals, Memory Leaks, and Performance Optimization

`[補收]` `[工程知識]` `[瀏覽器原理]` `[效能]`

這則和上一則剛好是「原理」與「實務」的一對：上一則教你怎麼**測出**洩漏，這一則解釋洩漏到底怎麼發生的。核心觀念只有一句——**V8 判斷一個物件死活的依據是「可達性」，不是「你還想不想用它」**：只要還能從根（全域變數、目前的呼叫堆疊、活著的閉包）走到它，它就不會被回收。

V8 把堆積分成 New Space（小、頻繁回收，因為大多數物件都短命）、Old Space（大、回收較少）、Large Object Space 與 Code Space；年輕代用 Scavenge（把活著的物件在兩塊半區之間搬來搬去），老年代用 Mark-Sweep-Compact（標記 → 清除 → 壓實消碎片）。現代 V8 再加上增量／並行／平行標記，把停頓壓到個位數毫秒。

四種最常見的洩漏都可以用「誰還抓著它」來解釋，範例都是幾行就看懂的：

```js
// 1. 忘了移除的監聽器：閉包把 bigData 一起養著
function attachHandler(el) {
  const bigData = new Array(1_000_000).fill("leak");
  el.addEventListener("click", () => console.log(bigData.length));
}
// 修法：元素移除時一併 el.removeEventListener("click", handler)

// 2. 沒清掉的計時器：store 永遠有人抓著
const intervalId = setInterval(() => store.refresh(), 5000);
clearInterval(intervalId);   // 修法：存下 id 並在適當時機清掉

// 3. 無上限的快取：Map 是強引用，永遠不會自己淘汰
const metadata = new WeakMap();   // 修法：改用 WeakMap（或自己實作 LRU 淘汰）
metadata.set(el, data);           // el 被移除時，這筆資料可以一起被回收

// 4. Detached DOM：節點從畫面移除了，但變數還抓著它
let cachedRow = document.querySelector(".row");
table.removeChild(cachedRow);
cachedRow = null;   // 修法：把參照斷開，否則整棵子樹都回收不掉
```

除錯流程也很具體：開 Chrome DevTools 的 Memory 面板 → 拍兩張 heap snapshot 比對「哪類物件變多了」→ 看 retainer path 查出是誰抓著它 → 在快照裡搜尋 "Detached" 找出離線的 DOM 節點。

`[補收]` `[效能]` `[架構]` `[React]` `[案例研究]`

### 5. use-webmcp-tool：把網頁功能宣告成 AI agent 可呼叫的工具

`[AI輔助開發]` `[React]` `[Web平台]`

Google Chrome Labs（Sarah Drasner 團隊）釋出的 React hook，解決一個正在成形的問題：**AI agent 要操作你的網站時，是要它去猜 DOM、截圖辨識，還是你直接告訴它「這個頁面提供哪些功能」？** WebMCP 這個開發中的標準選後者——網頁把自己的 JavaScript 函式註冊成可被發現、可被呼叫的「工具」。

這個 hook 的價值在於把 WebMCP 的命令式 API 包成 React 的宣告式寫法：**元件掛載時自動註冊工具、卸載時自動移除**，agent 看到的工具清單永遠跟目前畫面上有的功能同步：

```jsx
import { useWebMCP } from "use-webmcp-tool";

function TodoTools({ addTodo }) {
  const { supported, registered } = useWebMCP({
    name: "add-todo",
    description: "Add a new item to the user's active todo list",  // agent 靠這句判斷何時該用
    inputSchema: {
      type: "object",
      properties: { text: { type: "string" } },
      required: ["text"],
    },
    async execute({ text }) {   // agent 呼叫時真正執行的就是你自己的函式
      addTodo(text);
      return `Added todo item: "${text}" successfully.`;
    },
  });

  return registered ? <p>🤖 Agent tools ready</p> : null;
}
```

用生活化的方式說：以前是把 agent 丟進你家、讓它自己摸索每個按鈕在哪；現在是直接遞給它一張功能選單。要求 React 18+、ESM、附 TypeScript 型別，Apache-2.0 授權，目前約 161 顆星。對想提早佈局「網站要被 AI agent 使用」的團隊，是目前最小可跑的實驗入口。

### 6. TermDOM：用 HTML、CSS 和 DOM 寫終端機介面

`[DX工具]` `[Web平台]`

一個把**真的 DOM、真的 CSS 串接規則、真的排版引擎搬進終端機**的函式庫。它不是「產生看起來像 UI 的字串」，而是實作了一條瀏覽器式的渲染管線，只是最小單位從像素換成字元格；CSS 屬性被翻譯成 ANSI 顏色與樣式，DOM 一有變動就自動重繪。

意思是你既有的前端技能可以直接用：

```js
import { TermDOM } from "@b9g/termdom";   // npm install @b9g/termdom

const term = new TermDOM();
term.attach();
const { document } = term;               // 這是真的 document，有 querySelector、MutationObserver

document.body.innerHTML = `
  <style>
    .card { border: 1px solid #5fafff; padding: 0 1ch; }   /* 1ch = 一個字元寬，終端機版的長度單位 */
  </style>
  <div class="card">Content here</div>
`;
```

支援的範圍比想像中完整：CSS 盒模型、flexbox 與 table 排版、捲動、鍵盤／滑鼠／貼上事件、表單元素、Web Components、CJK 與 emoji 的字寬處理、選取與全螢幕模式，可跑在 Node、Bun、Deno 上，也能接任何前端框架。約 122 顆星，MIT 授權。

對需要寫 CLI 工具又不想學一套全新 TUI 函式庫的前端工程師，這是把既有知識直接遷移過去的路徑——尤其是排版邏輯，用 flexbox 排終端機畫面比手動算字元位置直覺太多。

### 7. Astro 7.2

`[Astro]` `[框架]` `[Build工具]`

Astro 7.2 最重要的是**實驗性的增量靜態建置**：程式碼與資料都沒變的預渲染頁面，這次建置直接跳過不重做。對內容量大的網站（部落格、文件站）這是建置時間從幾分鐘掉到幾秒的差別。

啟用方式與運作邏輯都很好懂——你要提供一把「內容有沒有變」的鑰匙，Astro 負責處理「程式碼有沒有變」：

```js
export default defineConfig({
  experimental: { incrementalBuild: true },
});

// 路由要從 getStaticPaths() 回傳 cacheKey
export async function getStaticPaths() {
  const posts = await getCollection('blog');
  return posts.map((entry) => ({
    params: { slug: entry.slug },
    props: { entry },
    cacheKey: entry.digest,   // 內容變了 digest 就變 → 這頁重建；沒變就沿用
  }));
}
// Astro 另外自動雜湊每個路由的模組圖（模板／layout／元件／資源）
// → 只有「模組雜湊」和「cacheKey」兩者都相同時才重用上次的產物
```

另外三項改進也都很實際：`session: false` 可以整個關掉 session runtime、把相關程式碼從 SSR bundle 移除，減少冷啟動的解析負擔（`Astro.session` 會變成 `undefined`，向後相容）；`astro preview` 新增背景模式，可以 `--background` 啟動再用 `astro preview status / logs / stop` 管理，接 CI 或 e2e 測試很方便；自訂 logger 的 entrypoint 現在接受相對路徑，不用再寫 `import.meta.url` 那串。

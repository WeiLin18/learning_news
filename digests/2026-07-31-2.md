## 工程知識 / 教學型（5）

1. **[CSS][工程知識] Get Ready For the Powerful CSS `border-shape` Property!**
   CSS 新提案 `border-shape` 讓邊框可以沿著任意形狀路徑繪製，而不只是矩形/圓角矩形，等於把 `shape()`／`corner-shape` 的形狀定義直接套用到 border 上，還能對 `border-width` 做兩值語法動畫，做出「描邊逐漸展開」的效果。這解決了過去要做不規則形狀邊框只能疊圖片或 SVG mask 的痛點。範例語法：
   ```css
   .badge {
     border: 8px solid crimson;
     border-shape: inset(0 round 40% 10% 40% 10%); /* 沿不規則圓角路徑描邊 */
   }
   ```
   來源：CSS-Tricks（優先來源）｜https://css-tricks.com/get-ready-for-the-powerful-css-border-shape-property/
   發布日期：2026-07-15（近期）

2. **[a11y][工程知識] The Siren Song of `ariaNotify()`**
   新的 `ariaNotify()` 方法（WAI-ARIA 1.3 規範）讓開發者用 JS 直接觸發螢幕閱讀器念出一段文字，不用再靠隱藏的 `aria-live` 區塊「騙」瀏覽器念出動態內容。文章同時提醒：這是「最後手段」工具，只有在真的沒有其他語意化方式時才該用，濫用反而會干擾使用者。範例：
   ```js
   el.ariaNotify("已加入購物車，共 3 件商品");
   ```
   目前 Firefox 150 已支援，Safari 尚未支援、macOS 上不穩定，使用前務必做 feature detection。
   來源：CSS-Tricks（優先來源）｜https://css-tricks.com/the-siren-song-of-arianotify/
   發布日期：2026-06-19（較早，約 6 週前）

3. **[CSS][工程知識] Why Isn't My 3D View Transition Working?**
   拆解一個很多人踩過的坑：用 View Transitions API 做跨頁 3D 翻轉動畫時，畫面看起來是「平的」，原因是瀏覽器預設會把參與轉場的元素攤平（flatten），除非你在**父容器**上明確設定 `perspective`，3D transform 才會真正生效。範例修正：
   ```css
   ::view-transition-group(card) {
     perspective: 1000px; /* 加在父層，不是子層本身 */
   }
   ```
   是一篇紮實的除錯型教學，對做轉場動畫的前端很實用。
   來源：CSS-Tricks（優先來源）｜https://css-tricks.com/why-isnt-my-3d-view-transition-working/
   發布日期：2026-06-15（較早，約 6.5 週前）

4. **[工程知識][架構] Under the hood of MDN's new frontend**

5. **[AI輔助開發][工程知識] Introducing the MDN MCP server**
   MDN 官方推出 MCP Server，把 MDN 的文件搜尋與瀏覽器相容性資料（Baseline 狀態）直接接進 coding agent / IDE，解決「LLM 訓練資料過舊，會建議已經過時或還沒被廣泛支援的 API」的問題（例如不知道某個 CSS at-rule 是否已達 Widely Available）。設定範例（在支援 MCP 的編輯器/agent 設定檔加入）：

6. **[Blog][AI輔助開發] Addy Osmani — My LLM coding workflow going into 2026**
   Google Cloud AI 的 Addy Osmani 分享他實際的 LLM 輔助開發工作流程：核心原則是「不要讓 AI 一次吐出一大包程式碼」，而是把任務拆成一個個小步驟（實作一個函式、修一個 bug、加一個功能），每步都審查再繼續；同時主張要用測試、監控、甚至「AI 審查 AI 產出的程式碼」來把品質關卡補起來。範例工作流程：
   ```
   1. 先寫/更新測試,描述預期行為
   2. 請 agent 只實作「讓這個測試通過」的最小改動
   3. Review diff → 若通過再進下一步,不累積大顆未審查的變更
   ```
   對想把 AI 輔助開發用得更可靠、而不是一次性生成整個功能的前端團隊很有參考價值。

## 前端技術棧 ＋ Web 平台主題（7）

9. **[AI輔助開發][Web平台] WebMCP — 讓網頁自己說明可以怎麼被 AI agent 操作**
   WebMCP 讓網站用宣告式的方式（HTML 屬性/JS API）標註頁面上的功能,讓瀏覽器內的 AI agent 不用再靠螢幕截圖或解析原始 HTML 來猜「這個按鈕是做什麼的」——後者又貴又脆弱,前端只要改個 class name 就可能讓 agent 失效。官方數據顯示,比起截圖+DOM 爬取,WebMCP 可以省下約 89% 的 token 用量。範例概念：
   ```html
   <button webmcp-tool="add-to-cart" webmcp-description="將目前商品加入購物車">
     加入購物車
   </button>
   ```
   Expedia、Booking.com、Shopify、Etsy、Target 等已在做早期實驗,對前端工程師來說,這代表「頁面的可操作性」以後可能要同時對人類使用者和 AI agent 兩種對象設計。
   來源：Chrome for Developers（優先來源）｜https://developer.chrome.com/docs/ai/webmcp
   發布日期：功能於 2026-02-10 隨 Chrome 146 Canary 首次推出（較早），文件頁持續更新中
